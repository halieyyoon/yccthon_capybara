# 대학생 프로젝트 팀원 매칭 커뮤니티 — 기술적 차별화 전략

## 배경 및 핵심 문제의식
기존 대학생 팀원 매칭 플랫폼(에브리타임, 링커리어, 렛플, 비긴메이트 등)은 대부분 **정적인 모집 게시판 + 자기신고형 프로필**에 머물러 있어 초기 이탈이 빠르고 매칭 신뢰도가 낮다.

이번 구상의 핵심 강점인 **AI 활용도·참여 온도(진지 vs 편함)·협업 지뢰(정 떨어지는 행동)·연세대 시작 후 타대 확장**을 실제 기술적 해자(Moat)로 발전시키기 위한 5가지 차별화 방향을 정리한다.

---

## 1. 링크드인 연동의 현실적 대안: 멀티소스 자동 프로필 빌더

### 기술적 제약 확인
- **LinkedIn 공식 API**는 파트너십 승인 없이는 개인의 경력·프로젝트를 외부 서비스에서 자유롭게 읽고 쓰는 양방향 동기화를 허용하지 않는다(일반 OAuth로는 이름·이메일·프로필 사진 등 기본 정보만 조회 가능).

### 차별화 구현 방안
- **입력 마찰 제거 (Multi-source Ingestion Pipeline)**
  - LinkedIn의 `PDF로 저장` 파일, 노션 포트폴리오, 기존 공모전 발표자료(PDF/PPT), GitHub 링크를 업로드하면 LLM 구조화 파이프라인이 경력·역할·기술 스택·사용 툴을 자동 추출해 프로필 템플릿 초안을 채운다.
  - 활동 이력이 적은 저학년·초보자는 짧은 대화형 Q&A를 통해 초안을 자동 생성한다.
- **역방향 내보내기 (Export for LinkedIn)**
  - 플랫폼에서 공모전·프로젝트를 완료하면 LinkedIn 경력/프로젝트 항목에 바로 붙여넣을 수 있는 국·영문 요약본과 **활동 검증 링크(Verified Page)**를 자동 생성해, API 제약 없이 중복 입력 불편을 해소한다.
- **증거 기반 프로필 (Proof of Work)**
  - GitHub 저장소 등을 연동해 단순 키워드 나열(“Python 가능”)이 아니라 최근 활동성, 실제 기여 비율, 주요 사용 라이브러리 등 검증 가능한 신호를 프로필에 반영한다.

## 2. 정적 설문을 넘어선 협업 궁합·지뢰 회피 매칭 엔진

**AI 활용도 / 참여 온도 / 정 떨어지는 행동**은 단순 체크박스로 두면 누구나 좋게만 작성해 변별력이 떨어진다. 이를 정교한 매칭 모델로 구조화한다.

- **시나리오 기반 성향 벡터화 (Situational Profiling)**
  - “AI 의존도: 상/중/하” 대신 실제 협업 상황 질문 3~5개(예: *“마감 전날 AI가 짠 코드가 돌아가긴 하는데 이해는 못 했을 때?”*, *“회의 전 아이디어 초안을 ChatGPT로만 뽑아온 팀원을 보면?”*)에 대한 응답으로 **실제 협업 스타일 벡터**를 생성한다.
- **Deal-breaker(지뢰) 자동 필터링**
  - 서술형으로 입력한 “협업 시 정 떨어지는 행동”을 LLM으로 정규화·임베딩(예: `연락 두절`, `출처 없는 AI 복붙`, `역할 떠넘기기`, `마감 직전 수정`)한다.
  - 한쪽이 극도로 기피하는 행동과 상대의 작업 스타일이 충돌할 경우 매칭 순위를 낮추거나 사전 합의 포인트로 안내한다.
- **개인 검색이 아닌 팀 조합 최적화 (Team Composition Engine)**
  - 기존 플랫폼의 “팀원 1명 검색”을 넘어, 현재 팀원들의 프로필을 묶어 **역량 보완성(부족한 직군·도메인)**과 **온도·리듬 일치성(목표 강도, 주당 투입 시간, 선호 작업 시간대, AI 활용 철학)**을 함께 계산한다.
  - 단순 점수 대신 **설명 가능한 매칭 근거**를 제공한다.
    - 예: *“목표 온도(수상 목표)·주당 15시간 일치 + 현재 팀에 없는 데이터 분석 역량 보완 / 참고: AI 초안 활용 방식은 사전 합의 권장”*

## 3. 공모전 공고 파싱 + 타깃 매칭·광고 모델의 기술적 결합

광고 수익 모델을 단순 배너가 아니라 **매칭 엔진의 일부**로 결합해 사용자 만족도와 광고 효율을 동시에 높인다.

- **공모전 공고 멀티모달 자동 구조화**
  - 주요 공모전·해커톤 포스터(이미지/PDF)와 요강을 수집·파싱해 `도메인`, `필요 직군 조합`, `심사 기준`, `예상 소요 기간`을 자동 추출한다.
- **공모전 기준 원클릭 팀원 추천**
  - 사용자가 관심 공모전을 선택하면 해당 대회 심사 기준과 도메인에 맞는 타 전공·타 대학 후보군을 자동 추천한다.
- **고효율 네이티브 광고**
  - 공모전 주최 측이 원하는 조건(예: *AI 구현 가능 + 금융/경영 전공 관심*)에 맞는 사용자에게만 해당 공모전을 추천하는 타깃팅 엔진으로 광고 단가를 높인다.
- **수익 모델 설계 시 주의점**
  - **유료 프로필 우선 노출**은 매칭 알고리즘 신뢰도를 떨어뜨릴 위험이 크다.
  - 개인 프로필 부스트보다는 **공모전 주최사 타깃 홍보 / 팀 모집 공고 상단 노출**로 수익화하고, 유료 노출은 명확히 구분 표시하는 편이 안전하다.

---

## 4. 확장 시 진짜 해자가 되는 협업 신뢰 그래프 (Trust Graph)

연세대에서 시작해 타 대학으로 확장할 때, UI는 쉽게 복제되지만 **축적된 협업 신뢰 데이터**는 복제할 수 없다.

- **학교 이메일 인증 + 프로젝트 완주 상호 인증**
  - 대학 이메일(`@yonsei.ac.kr` 등)로 신뢰 기반을 확보하고, 프로젝트 종료 후 팀원 간 상호 확인(Mutual Verification)을 통해 실제 완주 이력을 기록한다.
- **독성 없는 평판 시스템 설계**
  - 공개 별점이나 부정적 자유 리뷰는 명예훼손 분쟁과 커뮤니티 이탈을 유발한다. 대신 아래 두 가지로 분리해 축적한다.
    1. **공개용 긍정 강점 태그**: *마감 준수, AI 툴 활용 능숙, 발표 강점* 등
    2. **비공개 매칭 시그널**: *“이 사람과 다음 프로젝트도 함께하고 싶은가?”* — 외부 미공개, 내부 매칭 신뢰 점수에만 반영
- **2촌 검증 인재 추천**
  - 협업 이력이 그래프로 쌓이면 *“나와 함께 프로젝트를 완주했던 팀원이 추천한 타 대학 디자이너”*처럼 링크드인의 1·2촌 구조를 대학생 프로젝트 검증망으로 구현할 수 있다.

## 5. 오버엔지니어링 방지: 단계별 구현 로드맵

초기 구현 부담을 줄이기 위해 연세대 MVP부터 단계적으로 기술을 고도화한다.

| 단계 | 목표 | 핵심 기술 스택 / 구현 범위 |
|---|---|---|
| **1단계 (연세대 MVP)** | 빠른 검증 & 초기 인재 풀 확보 | 학교 이메일 인증, PDF/이력서 업로드 → LLM 프로필 자동 채우기, 구조화 필터(온도·시간·AI 활용도) + **자연어 팀원 검색**(예: *"진지하게 핀테크 공모전 나갈 디자이너, 주 10시간"*) |
| **2단계 (매칭 고도화)** | 매칭 품질 차별화 | 시나리오 기반 성향 임베딩, Deal-breaker 충돌 감지, 팀 단위 부족 역량 추천, 프로젝트 완료 후 상호 인증 + LinkedIn 복붙용 요약 자동 생성 |
| **3단계 (타대 확장 & 수익화)** | 크로스전공 네트워크 & 광고 | 공모전 공고 자동 크롤링/파싱 파이프라인, 2촌 협업 신뢰 그래프, 공모전 주최사 타깃 추천 광고 엔진 |

---

## 기술 설계 전 먼저 결정할 사항
1. **초기 타깃의 중심**: 개발·IT 해커톤(GitHub/기술스택 중심)부터 잡을지, 경영·마케팅·기획 공모전(문서/PPT/도메인 중심)까지 처음부터 열지에 따라 자동 프로필 파싱과 역량 검증 방식이 달라진다.
2. **매칭 UX 비중**: 사용자가 직접 검색·연락하는 **탐색형(마켓플레이스)** 중심인지, 공모전을 고르면 시스템이 팀 조합을 제안하는 **추천형(매칭 엔진)** 중심인지에 따라 초기 백엔드·AI 투자 우선순위가 달라진다.
