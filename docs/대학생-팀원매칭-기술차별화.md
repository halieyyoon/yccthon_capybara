# 대학생 프로젝트 팀원 매칭 커뮤니티 — 기술적 차별화 전략

## 배경 및 문제의식
기존 대학생 팀원 매칭 서비스(에브리타임, 링커리어, 렛플, 비긴메이트 등)는 대부분 **글만 올리는 게시판 + 본인이 적는 스펙 프로필**에 머물러 있어, 초기 이탈이 빠르고 실제 팀플 합이 안 맞는 경우가 많다.

이번 구상의 핵심 강점인 **AI 활용도 · 참여 온도(진지 vs 편함) · 협업 지뢰(정 떨어지는 행동) · 연세대 시작 후 타 대학 확장**을 경쟁사가 쉽게 따라 할 수 없는 기술 강점으로 발전시키는 5가지 방향을 정리한다.

---

## 1. 링크드인 연동의 현실적 대안: 파일만 올리면 자동 완성되는 프로필

### 기술적 제약 확인
- **링크드인 공식 API**는 특별 제휴 승인 없이는 외부 앱이 개인의 경력·프로젝트를 양방향으로 자동 동기화하는 것을 허용하지 않는다(일반 로그인 연동으로는 이름·이메일·프로필 사진 정도만 가져올 수 있음).

### 차별화 구현 방안
- **입력 부담 없애기 (자동 추출)**
  - 링크드인의 `PDF로 저장` 파일, 노션 포트폴리오, 기존 공모전 발표자료(PDF/PPT), GitHub 링크를 올리면 AI가 경력·역할·사용 기술·툴을 자동으로 뽑아 프로필 초안을 채운다.
  - 활동 이력이 적은 저학년·초보자는 짧은 대화형 질문 몇 개로 초안을 자동 생성한다.
- **링크드인 역방향 내보내기**
  - 서비스 안에서 공모전·프로젝트를 끝내면 링크드인 경력/프로젝트 칸에 바로 붙여넣을 수 있는 국·영문 요약과 **활동 확인 링크**를 자동 생성해, 두 번 입력해야 하는 불편을 해결한다.
- **실제 작업물로 검증되는 프로필**
  - GitHub 등을 연결하면 단순 “Python 가능”이 아니라 최근 활동량, 실제 기여 비중, 주로 쓰는 라이브러리처럼 객관적인 근거를 프로필에 함께 보여준다.

## 2. 단순 설문을 넘어선 협업 궁합·지뢰 회피 매칭

**AI 활용도 / 참여 온도 / 정 떨어지는 행동**을 단순 체크박스로 두면 누구나 좋게만 답해 변별력이 떨어진다. 이를 실제 매칭 로직으로 구조화한다.

- **실제 상황 질문으로 협업 성향 파악**
  - “AI 의존도: 상/중/하” 대신 짧은 협업 상황 질문 3~5개(예: *“마감 전날 AI가 짠 코드가 돌아가긴 하는데 이해는 못 했을 때?”*, *“회의 전 아이디어 초안을 ChatGPT로만 뽑아온 팀원을 보면?”*)로 진짜 협업 스타일을 분류한다.
- **협업할 때 절대 못 참는 행동(협업 지뢰) 자동 필터링**
  - 사용자가 적은 “정 떨어지는 행동”을 AI로 표준 항목(예: `연락 두절`, `이해 없는 AI 복붙`, `역할 떠넘기기`, `마감 직전 수정`)으로 정리한다.
  - 한쪽이 극도로 싫어하는 행동과 상대 스타일이 부딪히면 매칭 점수를 낮추거나, 첫 회의에서 미리 합의할 점으로 안내한다.
- **1명 검색이 아닌 4인 팀 조합 추천**
  - “팀원 1명 검색”을 넘어, 팀 전체를 묶어 **서로 부족한 역할 보완**, **온도·가능 시간표 겹침(When2Meet형 정기 회의 시간 추천 포함)**, **AI 활용 방식 조화**를 함께 계산한다.
  - 단순 숫자 점수 대신 **이유가 보이는 매칭 설명**을 제공한다.
    - 예: *“수상 목표·화요일 저녁 정기 회의 가능 일치 + 팀에 없는 데이터 분석 역량 보완 / 참고: AI 초안 활용 범위는 첫 회의에서 합의 권장”*

## 3. 공모전 공고 자동 정리 + 맞춤형 추천 광고 결합

광고 수익 모델을 단순 배너가 아니라 **매칭 기능의 일부**로 녹여 사용자 만족도와 광고 효율을 동시에 높인다.

- **공모전 포스터·요강 자동 정리**
  - 주요 공모전·해커톤 포스터(이미지/PDF)와 공고를 읽어 `분야`, `필요한 역할 조합`, `심사 기준`, `예상 기간`을 자동 정리한다.
- **공모전 기준 원클릭 팀원 추천**
  - 사용자가 관심 공모전을 누르면 해당 대회 심사 기준과 분야에 맞는 타 전공·타 대학 후보 조합을 바로 추천한다.
- **자연스럽게 섞여 나오는 맞춤형 추천 광고**
  - 공모전 주최 측이 원하는 조건(예: *AI 구현 가능 + 금융/경영 전공 관심*)에 딱 맞는 학생에게만 해당 공모전을 추천해 광고 단가와 클릭률을 높인다.
- **수익 모델 설계 시 주의점**
  - **돈을 낸 개인 프로필을 상단에 띄우는 방식**은 매칭 신뢰를 깨뜨릴 위험이 크다.
  - 개인 노출 부스트보다는 **공모전 주최사 맞춤형 홍보 / 팀 모집 공고 상단 노출**로 분리하고, 광고 표시를 명확히 두는 편이 안전하다.

---

## 4. 확장 시 따라 할 수 없는 경쟁력: 지인 검증 신뢰망

연세대에서 타 대학으로 넓힐 때 화면 디자인은 쉽게 베낄 수 있지만, **실제 프로젝트를 함께 완주한 신뢰 데이터**는 베낄 수 없다.

- **학교 이메일 인증 + 프로젝트 완주 상호 확인**
  - 대학 이메일(`@yonsei.ac.kr` 등)로 신뢰 기반을 만들고, 프로젝트가 끝난 뒤 팀원끼리 서로 확인해 실제 완주 이력을 기록한다.
- **악플 없는 건강한 평판 구조**
  - 공개 별점이나 부정 리뷰는 분쟁과 이탈을 부른다. 대신 두 가지로 분리해 쌓는다.
    1. **공개용 긍정 강점 태그**: *마감 준수, AI 툴 활용 능숙, 발표 강점* 등
    2. **비공개 재협업 의사**: *“이 사람과 다음에도 같이 하고 싶은가?”* — 외부에는 절대 비공개, 내부 매칭 점수에만 반영
- **지인 검증 팀원 추천**
  - 협업 이력이 쌓이면 *“나와 전에 완주했던 팀원이 추천한 타 대학 디자이너”*처럼 믿을 수 있는 2촌 인재를 우선 추천할 수 있다.

## 5. 처음부터 너무 복잡하게 만들지 않기: 단계별 구현 순서

초기 개발 부담을 줄이기 위해 연세대 첫 버전(MVP)부터 단계적으로 기술을 붙인다.

| 단계 | 목표 | 구현 범위 |
|---|---|---|
| **1단계 (연세대 MVP)** | 빠른 검증 & 초기 참여자 확보 | 학교 이메일 인증, 이력서 PDF 자동 입력, 2분 프로필(온도·가능 시간표·약점/강점·AI 스타일·지뢰), AI 모의회의 결과 카드 & 정기 회의 시간 추천 |
| **2단계 (매칭 고도화)** | 매칭 품질 차별화 | 협업 지뢰 정교 필터, 팀 단위 부족 역량 추천, 프로젝트 완료 후 상호 확인 + 링크드인 복붙 요약 자동 생성 |
| **3단계 (타 대학 확장 & 수익화)** | 여러 대학·전공 연결 & 광고 | 공모전 포스터 자동 수집·정리, 지인 검증 신뢰망 추천, 공모전 주최사 맞춤형 추천 광고 |

---

## 개발 전 먼저 정할 2가지
1. **초기 집중 분야**: 개발·IT 해커톤(GitHub/기술 중심)부터 시작할지, 경영·마케팅·기획 공모전(문서/PPT 중심)까지 처음부터 열지에 따라 자동 프로필 입력과 추천 기준이 달라진다.
2. **화면 중심축**: 사용자가 직접 찾아 연락하는 **탐색형**인지, 공모전을 고르면 시스템이 팀 조합을 제안하는 **추천형**인지에 따라 초기 개발 우선순위가 달라진다.
